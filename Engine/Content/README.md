# 单对局配置

想试不同流派和组合，可直接导入 [Templates 玩法模板](Templates/README.md)：六份 XML、八种编成，覆盖顺子叠毒、盾反、溢疗、净化、双人支援与遗物顺序对照。

`StandardSingleBattle.xml` 是按[《德州+肉鸽》](https://moonton.feishu.cn/wiki/KZGawy0ypiSMPtkmqwDcAKLFnle) revision 1278 整理的单局机制基线。依据为 2026-10-19 上一轮成功读取的正文与流程图；本轮未能刷新远端版本。它只有一个编成 `standard-single-battle`，一名玩家对一名普通敌人，标准 52 张牌，初始无遗物、无牌型升级。数值尚未定案，不作为正式平衡表。

`SingleBattleDemoNew.xml` 保留现有 Unity 场景配置和三个流派测试编成。新标准文件不自动替换它，避免改变当前 Demo 的体验。

## 使用

- 外部配置工具：导入 `StandardSingleBattle.xml`，选择“标准单对局”即可试玩、编辑和导出。
- Unity：XML 资产路径为 `Packages/com.kaya.battle-engine/Content/StandardSingleBattle.xml`；在 Host 的 XML 内容入口选择该资产，编成 ID 填 `standard-single-battle`，双方各绑定一名角色。也可调用已有 `ConfigureContent(xml, "standard-single-battle")`。配置在重新开局时生效。
- 规则层：沿用 `BattleContentCompiler.CompileXml` → `BattleContentFactory.Create` → `BattleSession.Execute(Start)`，无需新增宿主接口。

## 当前牌型配置

| 牌型 | 效果顺序 |
| --- | --- |
| 高牌、一对、两对 | 单体伤害，倍率区分强弱 |
| 三条、四条 | 全体敌人伤害 |
| 顺子 | 单体三段伤害；流血/中毒由可选遗物附加 |
| 同花 | 单体伤害，再按筹码恢复自身生命 |
| 葫芦 | 单体眩晕 → 自身净化 → 自身控制免疫 |
| 皇家同花顺 | 消灭所有存活敌人，绕过伤害与护盾结算 |
| 普通同花顺、五条 | 策划未单列技能，暂用单体伤害占位 |

这些对应关系没有写死在 Unity。每个 Hand 下的 Effect 都可以改种类、目标、数值、顺序，也可以将净化配置到其他牌型、敌人序列或遗物触发。伤害/治疗/加盾支持固定值；牌型效果另外支持总分系数或筹码系数。状态的期限、重复施加策略和已支持行为可配置。净化当前固定清除 Negative/Control 标签，不能用 XML 指定只清某一种状态。新的效果算法、状态行为、自由公式或敌人轮换 AI 仍须扩展规则代码。完整字段见[内容配置说明](../Runtime/Composition/Content/README.md)。

## 流程与未定数值

标准配置依据流程图在回合开始补满手牌；出牌后不立即补牌，弃牌后立即换牌。相较现有 Demo，这通过 `playRefill="NextPlayerTurn"` 配置，不修改引擎。流程图的筹码公式不含额外牌型基础筹码，因此本文件将所有 `points` 和 `pointsPerLevel` 设为 0；倍率与牌面筹码暂沿用现有表。

以下都是显式占位，后续直接改 XML：玩家生命 800、敌人生命 1200/攻击 240、每回合 3 能量、出牌与弃牌各消耗 1 能量、手牌 8 张、整场 3 次弃牌、每次最多出/弃 5 张、20 回合上限、每张弃牌 8 护盾、敌方阶段后清盾；顺子 3 段 × 总分 0.35、同花治疗筹码 × 0.2。正文有“抽 3–5 张”的概述，流程图则说补满手牌位而未给容量；8 张沿用 Demo，待策划统一。弃牌护盾是否必须有遗物的表述也未完全明确，本基线保留现有基础护盾，反伤需要遗物。

眩晕配置为跳过目标下一次行动窗口，免控持续到接下来的敌方阶段结束，用于当前单玩家回合制。若将来采用不同的阶段或行动结构，可改状态期限与行为；这不是全局“所有控制固定一回合”的规则。

保留三个未装备的流派模板：顺子逐段流血/中毒、弃牌盾反、同花治疗增幅与溢疗转伤。默认战斗不会触发这些能力。向 `Loadouts/Loadout[@id='baseline']` 添加 Relic 即可启用，例如：

```xml
<Loadout id="baseline" deckRef="standard-deck">
  <Relic instanceId="first-relic" ref="straight-dot"/>
  <Relic instanceId="second-relic" ref="discard-reflect"/>
</Loadout>
```

实例顺序就是获得顺序。模板中 DoT 每份 2 伤/触发 2 次、治疗增幅 50%、盾反与溢疗转伤 100% 均为待定数值，不代表策划已定案。

## 已知范围

本次只配置已有能力，不扩展上一轮保留的规则差异：

- 计分仍只统计成牌的计分牌子集，未覆盖流程图“所有打出牌都算筹码”的口径。将基础筹码设为 0 只能去掉额外基础值，不能改变选牌口径。
- XML 主战斗链路尚未接入“加筹码/加倍率/乘倍率”的计分遗物；现有 Numeric 修改的是伤害、治疗、护盾等结算量，不能冒充修改筹码或倍率。
- “解除出牌限制”尚无唯一明确口径，标准文件不擅自解释为免费出牌；精英召唤、Boss 塞废牌、局外塔罗、商店、金币与战后流程也不属于这份基础单局配置。

Unity 的配置和会话 API 保持兼容。净化与遗物顺序已更新规则语义，旧规则快照不兼容，必须重新开局；运行中的会话不接受 XML 热替换。新效果的专用美术/动画仍需表现层资源，本配置不声明已制作对应特效。
