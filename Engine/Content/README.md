# 单对局配置

日期版 [StandardSingleBattle-2026-10-20.xml](StandardSingleBattle-2026-10-20.xml) 保留当前标准版的三个可选对局和最高牌型计伤规则，供独立单局测试。此次核对策划 revision 1690 的毒素段落，默认仍为中毒者回合开始结算；未将其它段落的变动合并进本次配置。导入日期版后，在“状态配置 → 中毒·按层数伤害并衰减 → 周期伤害”中选择计时对象与结算时机，重新开局后生效：

| 计时对象 | 结算时机 | 规则 |
| --- | --- | --- |
| 中毒者 `Holder` | 回合开始 `TurnStarted` | 中毒者为玩家时在摸牌前，为敌人时在轮到其行动前结算。默认组合。 |
| 中毒者 `Holder` | 所属阵营阶段结束 `PhaseEnding` | 中毒者所属阵营所有角色结束行动后结算。 |
| 施加者 `Applier` | 回合开始 `TurnStarted` | 施毒者进入自身回合时，对其中毒目标结算毒伤。 |
| 施加者 `Applier` | 所属阵营阶段结束 `PhaseEnding` | 施毒者所属阵营所有角色结束行动后，对其中毒目标结算毒伤。 |

两种计时对象也都可以选“每次有效行动后 `ActionCompleted`”：计时对象完成出牌、主动弃牌防御或敌人实际行动后触发；一次多段攻击只结算一次，摸牌、直接结束回合和眩晕跳过不触发。回合开始和阶段结束时，眩晕不阻止毒伤结算。计时对象只决定何时触发，不改变毒伤打向中毒者的 `target="Self"`。

每次结算均按“当前层数 × 每层伤害”计算，再扣除配置的衰减层数。`timingSubject`、`timing`、`amount`、`stackDecay` 分别配置计时对象、时机、每层伤害与结算后的衰减；叠层使用 `reapply="AddStacks"`。原始标准文件继续保留。

局外验证入口另见 [StandardAdventure.xml](StandardAdventure.xml)：引用本页的三个标准对局，配置三章节点、塔罗、商店与休息收益；完整接口和存档边界见[局外规则说明](../Runtime/Composition/Adventure/README.md)。新增局外层不改变下面的标准单局配置。

`StandardSingleBattle.xml` 对齐[《德州+肉鸽》](https://moonton.feishu.cn/wiki/KZGawy0ypiSMPtkmqwDcAKLFnle) revision 1582（2026-10-20）及随后策划截图补充的玩家流程，并内置三个可选怪物对局。三种对局共用一名玩家、标准 52 张牌、计分与牌型规则，初始无遗物、无牌型升级。生命、攻击和怪物行为数值是机制验证用的测试占位。

| 编成 ID | 怪物 | 行为 |
| --- | --- | --- |
| `standard-single-battle`（默认） | 轮换小怪，600 生命 | 40 伤害 → 70 伤害 → 90 护盾，循环执行 |
| `standard-armored-summoner` | 护甲召唤精英，1800 生命 | 开局三层护甲，前 3 次主动命中各减伤 75% 并消耗一层；缺护卫时召唤两只轮换小怪，否则造成 90 群体伤害；本体加直属召唤物存活上限 3 |
| `standard-gluttony-boss` | 暴食Boss，2400 生命 | 常态 60 伤害并塞入 1 张废牌；生命不高于 50% 后，立即刷新未来 8 回合意图，改为 120 伤害和 3 张废牌 |

在 H5 配置工具载入标准 XML 后，可在对局模拟的编成选择中切换以上三种对局并重新开局，无需换 XML。敌人意图在玩家回合开始时锁定；召唤出的怪物从下轮开始行动。暴食产生的废牌进入弃牌堆，可弃置、不可出牌与计分，在牌库耗尽回收弃牌堆后才能抽到。独立的 [07—09 怪物模板](Templates/README.md) 继续保留，便于单独修改实验。

现有 `SingleBattleDemoNew.xml` 和[玩法模板](Templates/README.md) 已原地迁移到手动摸牌、保留手牌和弃牌结束回合的流程；不另存旧 XML。主题模板保留各自的数值和牌型技能，不作为标准平衡表。

## 标准回合

1. 开局洗牌并发满 8 张，不消耗手动摸牌次数。回合开始结算持有者的中毒，然后进入摸牌窗口。
2. 免费摸牌一次，可选 1–5 张或跳过。手牌上限 8；满手时拒绝摸牌且不扣次数。已有手牌超过 3 张时提示少摸，或先选择手牌弃置，再提交摸牌。选牌和取消不改变规则状态。
3. 每回合最多行动 3 次，出牌 1–5 张。效果摸牌独立于手动摸牌，可以超过手牌上限。出牌后不自动补牌。
4. 主动结束或行动用尽后，先结算 PlayPhaseEnd 遗物事件，再强制弃掉超出 8 张的部分，提交张数必须精确，不能跳过。不追加第二次防御弃牌；未弃的手牌保留至下回合。
5. 行动中弃牌防御默认消耗一次行动，获得“弃牌筹码总和 × 1”的护盾，并立即结束回合。摸牌前弃牌不消耗行动、不获得基础护盾；强制弃牌触发防御收益。

多玩家各自拥有窗口与次数，全部结束后敌方才行动。眩晕阻止出牌/防御行动，但保留摸牌窗口。牌库不足时洗回弃牌区；两区都空时停止摸牌，不报错。

## 计分与牌型

默认 `总分 = floor(计分牌筹码 × 倍率)`。**按最高牌型确定计分牌、等级与倍率，兼容的机制分别结算**；不把低级牌型的基础伤害再次相加。踢脚牌不贡献筹码或倍率；`kickerScoring="AllCards"` 或遗物 `RuleValue key="AllCardsScore" delta="1"` 可让全部打出牌进入计分。计分遗物依次处理加筹码、加倍率、乘倍率，同层按获得顺序。

| 牌型 | 标准效果 |
| --- | --- |
| 高牌 / 一对 / 两对 | 单体伤害；基础倍率 1 / 2 / 4 |
| 三条 / 四条 | 全体敌人伤害；基础倍率 2 / 4 |
| 顺子 | 基础倍率 2；每张出牌一击，本牌计分筹码 × 最高牌型倍率，每击后立即给仍存活的受击目标加 1 层毒 |
| 同花 | 伤害按最高牌型；独立治疗 floor(全部有效出牌筹码 × 同花一级基础倍率 × 20%)，可与三条群攻、顺子逐张叠毒等兼容机制同时触发 |
| 葫芦 | 按葫芦最高计分群攻一次，再眩晕、净化自身、获得控制免疫；不再额外结算对子伤害 |
| 皇家同花顺 | 沿用现有消灭效果，本次未改绝杀规则 |
| 普通同花顺 | 按同花顺倍率逐张伤害、叠毒，再叠加同花治疗 |
| 五条 | 保留现有单体伤害占位 |

标准单体优先攻击最低生命敌人。同一个 `retargetChain` 的连续攻击击杀后，后续伤害转向最低生命存活敌人；状态跟随刚完成的那一击，死亡目标不会获得状态。

中毒为可叠层状态：持有者行动前受到“每层伤害 × 当前层数”，随后减层；标准每层 1 伤、减 1 层。重施只加层、不刷新期限。配置 ID 继续使用 `bleed` 保持引用，显示名改为中毒。标准 5 张顺子共 5 击、每击 1 层；遗物放宽为 3 张时共 3 击、3 层。毒杀敌人后不再执行其行动。

## 可配置项与接口

手牌上限、出牌最小/最大张数、行动次数、摸牌张数/次数/提示阈值、开局发牌、效果摸牌溢出、弃牌是否消耗行动/结束回合、结束时防御和强制弃牌收益都在 Player 中配置。牌型步骤、目标、筹码表、倍率、中毒伤害/减层和遗物计分也可独立配置。完整字段见[内容配置说明](../Runtime/Composition/Content/README.md)。

连续攻击支持固定 Effect 步骤，或 `perSubmittedCard="true"` 按实际出牌逐张展开；遗物也可 AddHits，额外攻击保留 OnHitStatus。标准顺子使用逐张展开和 CardScoreScale，不再固定 3 段。玩家生命 800、三种怪物的生命/攻击/召唤参数、第 20 回合后每轮叠加 20 伤害的狂暴值、同花基础倍率 4 及升级增量仍是测试配置，未做平衡验证。

- 配置工具：导入标准 XML，进入对局模拟，先选择轮换小怪、护甲召唤精英或暴食Boss，再开局；选择摸牌张数或跳过，之后按窗口出牌/弃牌。H5 展示独立于 Unity 工程。
- Unity：包路径 `Packages/com.kaya.battle-engine/Content/StandardSingleBattle.xml`，Host 编成 ID 为 `standard-single-battle`。Scene3D 适配器新增 `DrawCards`、`SkipDraw`、`DiscardBeforeDraw`、`ConfirmOverflow`，HUD 提供对应入口。
- 规则层：`BattleContentCompiler.CompileXml` → `BattleContentFactory.Create` → `BattleSession.Execute(Start)`；新增命令 `Draw`（drawCount）、`SkipDraw`、`DiscardForDraw`、`ConfirmOverflow`、`FinishTurn`。`EndTurn` 请求结束出牌阶段，最后用 `FinishTurn` 确认结束。非法提交不改变状态。

规则契约 `battle-content.6`、战斗规则 `combat.12`，加载新配置或切换编成后重新开局。怪物轮换、条件选招、护甲、召唤和废牌使用[可配置行为契约](../Runtime/Composition/Content/EnemyBehavior.md)。绝杀与自由脚本公式未改；局外使用独立 `StandardAdventure.xml` 组装，H5 占位图与动画不接入 Unity 表现层。

## revision 1582 扩展

同花支持 3—5 张，顺子和同花顺默认仍需 5 张。`minFlushCards` / `minStraightCards` 可配置，遗物也可通过同名 RuleValue 调整。弃牌结束回合由 `DiscardEndsTurn` 遗物规则覆盖；`RetainBlock=1` 可保留玩家护盾。RuleValue 支持 `(基础值 + 全部 delta) × 全部 multiplier` 后向下取整并按参数限界处理。

标准配置清空敌方阶段结束时的敌方护盾、以及玩家下回合开始前的玩家护盾。`roundLimitBehavior="Enrage"` 在第 20 回合结束后进入狂暴，第 21 回合伤害 +20，第 22 回合 +40，以此类推；`enrageDamagePerRound` 为暂定测试值。`Lose` 仍可用于其他主题模板。

边界遗物支持 `BeforeDraw`、`Draw`、`Reshuffle`、`PlayPhaseEnd`、`TurnStarted`、`BattleEnded`，原有 PhaseStarted/PhaseEnding 对应团队回合开始/结束，敌人的 TurnStarted 对应行动前。卡牌边界携带实际卡牌 ID、当前手牌数、摸牌来源；`amountPerHandCard` 可配置每张留手牌追加护盾/治疗/伤害。效果摸牌继续派发边界，限制递归次数，整条失败回滚。`DiscardByEffect` 为规则调用方提供效果弃牌入口，携带 `Effect` 类型，不消耗玩家行动。

Boss 预告条通过纯查询 `PreviewEnemyIntents` 提供，在当前战场条件下推算未来八轮；未来玩家操作、状态和新增召唤可能改变之后的预测。当前意图仅在配置的血量阈值变化时即时重选。召唤 `limitScope="Summoner"` 按本体及直属召唤物统计；`consumeFailedSummon="false"` 保留失败召唤的使用次数和轮换游标。Boss 若新增召唤技能可配 `livingLimit="6"`，暴食默认仍为塞废牌。

绝杀与其金币回收仍不在本次修改范围内；新增局外验证流程使用节点配置的固定战后金币奖励。

## 策划补充：中毒、同花与兼容机制（2026-10-20）

`HandRule.combineCompatibleEffects="true"` 将最高计分牌型与兼容机制分开。同花三条按同花计分群攻，同花葫芦按葫芦计分群攻并控制、净化、免控、治疗；皇家同花顺仍走原有强制消灭。`FlushBonus` 在满足同花条件时额外执行一次治疗。H5 预览分别显示计伤牌型与生效机制。

治疗按确认口径使用同花一级基础倍率，独立于伤害牌型的倍率、计分遗物和同花等级。当前同花基础倍率 4，20 筹码治疗 `floor(20 × 4 × 0.2) = 16`；可修改 Scoring 中 Flush 的 multiplier 或 FlushBonus 的 amount。专门的 HealingDone / HealingReceived 遗物仍可修正最终治疗。无效牌不贡献治疗筹码。

逐张攻击从权威计分记录读取本牌计分贡献，使用最高牌型的最终倍率。新模式累计取整分配尾差，保证各击合计等于统一计分的总伤害；牌型及遗物的全局加筹码仅计入首张一次，避免丢失或重复。每击紧接着处理 OnHitStatus，后续攻击能看到已叠加的状态。XML 也支持固定层数加按实际出牌张数增长的层数，标准仅配置固定 1 层。

例如同花 `2、3、4、5、6` 以同花顺倍率 8 计伤：五段合计 160，附加五层毒，治疗仍为 16。非同花 `7、7、7、8、8` 按葫芦倍率 4 对每个敌人造成 148，再触发控制与自身净化、免控。
