# 单章七站体验内容

整局入口配对读取 `SingleChapterBattle.xml` 与 `SingleChapterAdventure.xml`。这是一套独立体验配置，保留原标准单局和三章配置供原测试与场景使用。

## 多文件入口与独立单局

战斗定义现在以 `SingleChapter/` 下的模块为维护源；`SingleChapterBattle.xml` 保留为兼容导出，供现有冒险入口、H5 编辑器等单文件消费者使用。修改模块后需重新导出；回归测试校验两者编译指纹相同，防止数值漂移。`SingleChapterAdventure.xml` 继续负责地图、商店和经济，不由战斗 Import 加载。

| 入口 XML | Encounter ID | 用途 |
| --- | --- | --- |
| [Battle1.xml](SingleChapter/Battle1.xml) | `single-chapter-battle-1` | 小怪一独立测试 |
| [Battle2.xml](SingleChapter/Battle2.xml) | `single-chapter-battle-2` | 小怪二独立测试 |
| [Gatekeeper.xml](SingleChapter/Gatekeeper.xml) | `single-chapter-gatekeeper` | 流血精英表现开发 |
| [Wrath.xml](SingleChapter/Wrath.xml) | `single-chapter-wrath` | 暴怒与五只手的独立表现开发 |
| [AllBattles.xml](SingleChapter/AllBattles.xml) | 上述四个 | 整章战斗配置与兼容导出 |

每个单局入口引用 `Shared.xml`、对应 `Rules/*.xml` 和 `Enemies/*.xml`，自身仅定义本场 `Encounters`。共享配置分为 `Players.xml`（生命、能量、手牌/行动规则）、`Hands.xml`（牌型计分与效果）、`Statuses.xml`、`Relics.xml`、`Decks.xml`、`Loadouts.xml`。修改一个模块即可被全部相关单局复用。独立启动使用基础玩家及初始构筑；冒险累计生命、遗物、牌组和阶段状态仍由冒险宿主或测试装配输入，不会自动继承。

在 BattleToolkit 仓库目录运行：

```powershell
dotnet run --project Build/BattleToolkit.Host -- --bundle Engine/Content/SingleChapter/Wrath.xml --start single-chapter-wrath
dotnet run --project Build/BattleToolkit.Host -- --bundle Engine/Content/SingleChapter/AllBattles.xml --export Engine/Content/SingleChapterBattle.xml
```

Unity 的 `XmlBattleSessionSource` 绑定入口及 Encounter ID 后，在 Inspector 点击“收集并校验 XML 依赖”，即可保存所需 TextAsset 引用；运行时不依赖磁盘路径。更改 Import 关系后需重新收集。随后沿用现有 `BattleSceneHost` 开局、重开与表现适配流程。单局入口跳过冒险前置关卡，但不会跳过敌人自身行为阶段；指定阶段状态可通过现有会话测试/管理接口构造。

玩家每回合3点能量，出牌与弃牌各消耗1点。2026-10-26 起，出牌后立即按 `playRefill="AfterAction"` 补至8张手牌；弃牌仍按弃掉的张数补牌。EnergyOnly 模式尊重出牌补牌配置，包括耗尽最后一点能量的那次出牌。

单章地图和经济循环沿用主案 revision 3869 / 3873，基础休息回血为 **20**；守门人与暴怒现接入 2026-10-22 确认的新版战斗规则。主角、怪物、同花与饮血治疗采用主案 revision **4357** 的本次更新，同花治疗按用户确认的 **50%**。不接入推币机。

## 路线与数值

```text
小怪一 → 宝箱 → 小怪二 → 商店一 / 休息一 → 守门人 → 商店二 / 休息二 → 暴怒
```

两个补给位置各自二选一，选择后汇合到同一主线。XML 共九个节点定义，每条实际路线均为七站、一个章节。

| 站点 | 配置 ID | 遭遇 / 收益 |
| --- | --- | --- |
| 小怪一 | `battle-1` | `single-chapter-battle-1`；10 回合；350 血、攻击 15；50 金币 |
| 宝箱 | `chest` | 进场自动开箱；100 金币和一件本局未获得的道具 |
| 小怪二 | `battle-2` | `single-chapter-battle-2`；10 回合；400 血、攻击 15；60 金币 |
| 补给一 | `shop-1` / `rest-1` | 商店或休息 |
| 守门人 | `elite` | `single-chapter-gatekeeper`；20 回合；800 金币 |
| 补给二 | `shop-2` / `rest-2` | 商店或休息 |
| 暴怒 | `boss` | `single-chapter-wrath`；20 回合；胜利完成本局 |

血量与伤害取整沿用战斗引擎向下取整。第一场小怪血量为 **350**，第二场为 **400**，两场的两种轮换动作均造成 **15**；保留原动作顺序和表现。第二站生命倍率改为 1，避免第二场再乘旧的 1.25。两场小怪均仅进行攻击，无护盾或特殊机制。各场达到回合上限失败。

七站已移除所有牌型的固有基础分及每级基础分增长；普通战、精英、Boss 使用同一配置。2026-10-26 启用 `exclusiveHandEffects=true`：每次只执行一个最高牌型的基础效果；不再将包含的对子、三条、四条技能自动合并。同花覆盖高牌、一对、两对、三条；四条高于同花。原本就是五张的顺子、葫芦、五条与同花组合时，保留原效果并增加治疗，没有额外 ×5。明确要求包含某组合的遗物仍可检查 `CompatibleCategories`，但不因此附加该组合的基础技能。

当前共13种最终表现身份，由 `HandAttackInfo.FinalType` / `HandGuideCandidate.FinalType` 提供。以下为一级、无遗物数值；“点数和”只统计参与该牌型计分的有效牌，群攻数值为每个目标受到的伤害。

| 最终牌型 | 计分牌 | 伤害与技能 | 治疗 |
| --- | --- | --- | --- |
| 高牌 | 最高一张 | 点数 ×1，单体一次 | 无 |
| 一对 | 对子两张 | 点数和 ×2，单体一次 | 无 |
| 两对 | 两组对子四张 | 点数和 ×3，单体一次 | 无 |
| 三条 | 三张同点数牌 | 点数和 ×3，全体一次 | 无 |
| 顺子 | 五张顺子牌 | 点数和 ×3，按顺序逐张攻击；每击叠毒，击杀后后续段可转火 | 无 |
| 同花 | 五张同花色牌 | 五张点数和 ×4，单体一次；覆盖内部对子、两对、三条 | 五张基础点数和 ×50% |
| 葫芦 | 三条与对子共五张 | 三条点数和 ×4 群攻，再对子点数和 ×4 指定目标；全体眩晕、自身净化和免控 | 无 |
| 四条 | 四张同点数牌 | 点数和 ×4，全体一次；即使五张同花也不附加治疗 | 无 |
| 同花顺 | 五张同花顺子牌 | 与顺子相同；使用顺子的倍率和等级，保留逐张、中毒、转火 | 五张基础点数和 ×50% |
| 五条 | 五张同点数牌 | 点数和 ×12，全体一次 | 无 |
| 同花葫芦 | 同花色的三条与对子 | 与葫芦相同，保留两段伤害、眩晕、净化和免控 | 五张基础点数和 ×50% |
| 同花五条 | 五张同点数同花色牌 | 与五条相同，点数和 ×12，全体一次 | 五张基础点数和 ×50% |
| 皇家同花顺 | 同花色10JQKA | 全体直接消灭，独占分支，不附加顺子的中毒 | 基础30 |

治疗独立使用有效同花牌的基础点数，与伤害倍率、牌型等级解耦；最终向下取整。心连心将50%加到80%。同花2579K伤害144、治疗18；同花7772K按同花计伤144、治疗18，不附带三条群攻。三条777可单独打出，改为每个敌人63伤害。葫芦33322为全体36、指定目标追加16；同花葫芦仍为36＋16，另治疗6。五条77777每个敌人420伤害，同花五条伤害不变，另治疗17。

A 始终使用配置的14点；A2345仅在顺子判型及攻击顺序中视A为低位。普通与同花A2345均造成42、6、9、12、15五段伤害，共84；同花版本另治疗14（心连心22）。中毒当前仍每击1层、每次结算减1层；可选的按点数中毒接口会叠28层，减半衰减方案尚未实现。皇家绝杀与历史标准单局、旧三章模板保留原规则。

复合牌型共用原牌型的成长：同花顺使用顺子等级；同花葫芦使用原三条/对子分项等级；同花五条使用五条等级。为保持核心扑克与存档类别兼容，`Pattern.Category` / `Score.Category` 的同花葫芦、同花五条仍分别为 FullHouse / FiveOfAKind；表现层应读取 `FinalType`，不要只用核心类别猜测名称。同花顺的最终类别仍是 StraightFlush，但普通分支读取 Straight 的计分规则；皇家分支保留原有独立绝杀。

本次验证：`dotnet test Tests/BattleToolkit.Tests.csproj --configuration Release -m:1`，**1875/1875通过**。覆盖13种最终身份、互斥牌型、预览/实际结算、查询、升级、遗物、治疗取整、A高低顺及旧模板。未运行Unity场景验收；已初始化的战斗不会热读XML，新配置需重新初始化对局。

起始金币沿用 30，遗物栏容量为 12，牌库最低 5、最高 128；这些都是 `AdventureContent` 根配置。玩家基础生命为 **120**；当前仅保留已实现的愚者开局天赋，最大生命 +20%，七站初始生命及上限均为 **144**。未将旧三章的通关解锁占位天赋带入体验版。

## 品质与经济

十二件道具沿用 `final.xml` 定义的效果和售出价格，显式添加 `quality`，与实例的升级 `Level` 无关。

| 品质 | 道具定义 ID | 商店买入价 |
| --- | --- | --- |
| 0 | 10001、10002 | 10 |
| 1 | 11002、11003、11004 | 20 |
| 2 | 12001 | 30 |
| 3 | 13001、13002、13003、13004 | 50 |
| 4 | 14001 | 100 |
| 5 | 15001 | 每个报价独立随机 50–200 |

空 `<Shop />` 使用全部十二件道具作为候选池。商店每次进场生成四个报价，已持有的唯一道具不入池，非唯一道具可以占据多个不同报价位。购买后该报价售罄，不补货；预览、页面重开和恢复存档都不会重抽。

三个改牌服务分别计次：删牌 45、复制牌 20、改花色 30。第 1–3 次维持基础价格，第 4–10 次逐次 ×1.1，第 11 次开始逐次 ×1.07，内部保留小数，支付与显示价格四舍五入。

休息进场固定恢复 20 生命，不超过上限。玩家可直接离开，或免费抽奖一次。高阶道具增减、两件低阶道具、金币增减三类结果各占三分之一。高阶为品质 3–4，低阶为品质 0–2，金币为 0–500；金币余额最低为零。道具奖励满栏时进入待领取队列，逐件选择替换一个已持有实例或放弃，处理完后才能离开。

## 精英与暴怒规则

守门人按 2026-10-22 用户截图更新为每轮攻击 +5、每层流血增伤 30%，同步日期版标准 `.21.xml` 与独立流血精英模板；暴怒保留已确认规则，保留 `summoner` / `wrath` 模板 ID 和 `single-chapter-gatekeeper` / `single-chapter-wrath` 遭遇 ID，宿主的场景及美术映射继续使用原入口。2026-10-23 的牌型数值对齐不修改敌人、道具或经济配置。

- 守门人为 **800 生命**的流血精英，初始攻击 **8**，全场每轮增加 **5**；交替执行半攻伤害后叠加 3 层流血、一次全攻普攻。流血每层使敌方主攻击承伤增加 30%，施加者行动结束减 1 层；新流血在本次伤害后施加。没有旧入场护甲或护卫召唤。按当前取整规则，前四回合攻击为 8／13／18／23，伤害为 **4／20／11／43**，回合结束后的流血层数为 **2／1／3／2**。
- 暴怒本体 **2000 生命**，四饮血手和一束缚手各 **1 生命**。`D = 8 + 5 × 存活手数 + 10 × 成功蓄力次数`；常规顺序为普攻、普攻、龟缩、蓄力。龟缩刷新两次最终免伤，蓄力永久加 10；控制跳过行动时不推进序列或蓄力。
- 五手齐全且本体可行动时，第 5 轮预警、第 6 轮在常规动作后追加 3D 大招，正常下一组为第 11/12 轮；断手或到期无法行动会取消并重新冷却 5 轮。第 12 轮先蓄力再放大招，未受其他修正时伤害为 **189**。
- 手在死亡轮 R 的 **R+8 敌方阶段开始**独立再生，同轮到期全部复活；五手不参与冒险生命倍率，本体沿用现有倍率。手不接受正向加攻或数值护盾。饮血手先结算自己的毒伤，存活且可行动才各治疗本体 **10**（四只合计 40；束缚手不治疗）；本体随后结算自己的毒伤。束缚按全场第 5、10、15、20 轮使玩家跳过下一行动窗口，免控可以阻挡，错过不补发。
- 本体死亡即胜利；玩家替死立即中止敌方阶段。完整第 20 轮结算后判负，不消耗替死；护盾沿用玩家回合开始清除。七站不再使用旧五手联动、半血复活或旧 1700 血暴怒。历史标准 XML、旧模板和三章冒险仍保留。

内容指纹随本次接入变化，旧配置生成的存档会按既有恢复规则拒绝加载；本次没有增加存档迁移。

## 验证

从 Unity 仓库根目录执行：

```sh
bash Tools/test-poker-engine.sh SingleChapterContentTests SingleChapterScoringTests AdventureEconomyTests SingleChapterEnemyRulesTests
```

`SingleChapterContentTests` 保留原四条路线及经济回归：检查节点、品质、回合上限及两场小怪动作顺序，并用低生命敌人隔离经济流程，覆盖入场预览、金币发放、固定库存与限购、休息可跳过/只抽一次、永久改牌、每个检查点恢复、七站结束和单次结算。

`SingleChapterEnemyRulesTests` 单独加载真实七站战斗配置，不把目标敌人替换成 1 血夹具：验证精英四轮实际伤害和流血层数、暴怒两组预警/大招与第 12 轮 189 伤害，并沿真实七站路线进入精英/Boss，验证冒险存档恢复后的流血、逐手再生、大招和 20 轮判负。前置无关战斗通过公开管理员入口结束，随机宝箱道具在目标战前清空以隔离数值；需要持续承伤的长回合用例仅通过公开管理员入口提高测试玩家生命，不改真实敌人。另以正常生命验证基础 120／愚者 144、实际小怪血量与攻击及玩家死亡。四手治疗 40／断一手 30／再生后恢复 40 属于提高测试玩家生命的长回合检查，逐敌方阶段核对，不将束缚后的自动连续推进当作单轮。规则测试不替代 Unity 场景验收。
