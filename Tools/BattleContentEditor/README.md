# 战斗内容工坊（本地 HTML 配置工具）

外部配置工具：十类中文表单、关联配置选择、XML 导入/导出、浏览器草稿、统一 C# 校验和对局试玩。试玩直接运行现有纯 C# 规则引擎，无需打开 Unity；不读写 Unity SO、场景或战斗存档。

## 启动

命令行也支持多文件配置（在仓库根目录执行）：

```powershell
dotnet run --project Build/BattleToolkit.Host -- --bundle Engine/Content/SingleChapter/AllBattles.xml
dotnet run --project Build/BattleToolkit.Host -- --bundle Engine/Content/SingleChapter/Wrath.xml --start single-chapter-wrath
dotnet run --project Build/BattleToolkit.Host -- --bundle Engine/Content/SingleChapter/AllBattles.xml --export Engine/Content/SingleChapterBattle.xml
```

三个命令依次用于递归加载并校验、用固定种子实际创建/启动单局、导出兼容单文件。错误输出原文件与行列；失败退出码为 1。导出前统一做语义校验，避免输出部分内容。HTML 表单当前仍编辑单文档；多文件请先导出后导入，不直接将带 Import 的入口拖入表单。单章模块为维护源，表单里的临时试玩修改不会自动写回各模块。

Windows 双击仓库根目录 `start.cmd`；macOS 双击 `start.command`。缺少 .NET 10 SDK 时，启动器从 Microsoft 官方下载安装到本仓库 `.runtime/dotnet`，随后构建并打开默认浏览器。不需要 Unity、Python、Mono 或 Node；首次启动需要联网。

默认地址 **http://127.0.0.1:18767**，请保留终端窗口。启动失败可以按 R 重试。规则源码修改后重启服务；XML 修改后重新开局。详细参数与排错见 [一键启动](../../scripts/README.md)。

沿用已选定的服务端口。端口被占用时先检查是否是现有工具，复用现有服务或停止后在同一端口重启，不额外启动另一份服务。浏览器草稿与冒险存档按地址/端口隔离；请使用启动器输出的 `127.0.0.1` 地址。

## 策划使用流程

1. 没有本地草稿时，首次打开自动载入日期最新的 `Engine/Content/StandardSingleBattle-日期.xml`；也可点击“载入功能示例”熟悉配置，或导入现有 XML。已有草稿会保留并提示恢复。
2. 左侧按战斗配置、角色与构筑、战斗能力、基础规则分组；搜索名称或 ID，打开具体条目。
3. 修改中文表单；空白可选字段表示继承默认值，显式填入 `0` 与留空不同。高级参数默认折叠。
4. 引用可输入 ID、用候选列表选择、打开可搜索的选择窗口，或点击 `+` 新建后自动引用；“查看”可跳转到定义。侧栏展示引用和被引用关系。
5. 编辑后自动延时调用 C# 校验，也可手动点击“校验内容”。点击错误或警告定位配置；字段级检查只提示输入，不能代替 C# 语义校验。
6. “保存草稿”或 Ctrl/⌘ S 保存本浏览器草稿；编辑会自动保存。第一次打开已有草稿时先提示恢复，不自动覆盖旧草稿。
7. “导出 XML”对当前修订重新执行 C# 校验，只有通过才下载。警告可导出；错误不能导出。源码区有未应用内容时，需要先应用或放弃修改。

十类内容：计分规则、公共战斗规则、牌型效果、状态配置、遗物配置、玩家模板、敌人模板、初始牌组、初始构筑、对局配置。嵌套行为、条件、效果与目标用相同表单编辑，可新增、移除和上下调整顺序。新建牌型规则会生成十种牌型；自定义计分由当前 C# 默认表展开；牌组可以一次添加标准 52 张牌，再编辑单张。

牌型步骤 ID 与效果顺序分开，重排不改 ID。遗物步骤选择器的“浏览步骤来源”只帮助列出指定规则/牌型的步骤，不写入遗物配置，也不假定所有玩家使用同一套牌型规则。修改/移除被匹配的步骤会展示可能受影响的遗物条目，实际对局组合仍由 C# 校验。

定义 ID 重命名时，会询问是否同步更新同类型引用；有引用的定义必须选择替代定义后才能删除。显示名称可自由修改。新增和复制自动生成不冲突的标识；复制构筑不会运行或消耗遗物。

## 对局试玩

1. 打开“对局试玩”，点击试炼卡片或下拉框选择对局。日期版标准 XML 内置轮换小怪、流血精英、暴食 Boss、暴怒·千手四场试炼，以及带十二件道具的独立测试单局；普通与精英分别使用 10 / 20 回合上限，Boss 保留原配置。已有其他配置时可用“载入标准试炼”载入；有未保存编辑会先提示确认。选择试炼不会自动替换正在进行的对局，点击“用当前配置开新局”才生效。
2. 填写固定种子并开局。工具会重新校验当前内容包，成功后才替换旧对局；失败时显示诊断并保留原对局。XML 预览中的修改需要先应用。
3. 新版标准自动补牌；点选手牌，查看牌型和结算预览，再出牌或弃牌。需要手动选敌时，按提示选择每组目标；多玩家配置可切换当前可行动玩家。结束出牌阶段后，按规则保留或整理手牌，再完成回合。
4. 横版战场左侧是玩家，右侧是敌人，敌人头顶显示下一次行动意图。生命条、护盾、增益/减益、顶部遗物图标随真实规则状态更新；悬停或键盘聚焦图标查看详情。展开底部“战斗记录”查看每步结算。
5. 暴食 Boss 默认将废牌塞入弃牌堆，牌库耗尽后才会洗回。塞牌时显示即时提示，牌堆角标显示废牌数量；点击牌库或弃牌堆可查看按牌面合并的内容，不展示摸牌顺序。废牌进入手牌后显示独立“废牌”卡面，明确标注不可出牌、可弃牌。 在敌人行为的“生成卡牌”中可设置放入区域和插入位置：抽牌堆支持随机洗入、牌顶、牌底，也可直接入手。抽牌堆不填位置时默认随机洗入；标准 Boss 仍默认进弃牌堆。详见[塞牌配置](../../Engine/Runtime/Composition/Content/EnemyBehavior.md#塞牌)。
6. 主动道具在手牌上方选择；六面骰需再选择另一件持有道具。先查看结算预览，再点击使用；只有玩家行动阶段且有剩余行动点时可用，道具本身不扣行动点。次数、战斗冷却和转盘状态由规则层返回，预览不会消耗次数或随机序列。道具测试单局用于集中验证这些入口。
7. 表单修改不会改变正在进行的对局。重开时应用当前配置；同一配置和种子、同样的操作会重现相同发牌及结算。

标准流血精英当前为 500 生命、8 初始攻击，每完整回合结束攻击 +5，施法 / 普攻顺序循环。施法先造成当前攻击 0.5 倍伤害，再施加 3 层流血；每次精英实际行动结束减 1 层，眩晕跳过不减。流血每层使敌人对玩家攻击承伤额外 +30%，在护盾前合成一次伤害，不放大道具自伤、周期伤害和反伤，可累积、可净化。敌人头顶显示真实引擎预览、加减层与攻击成长，流血增伤说明读取规则审计证据。旧 `08_ArmoredSummoner.xml` 仍保留原护甲召唤机制；新模板为 `11_BleedingElite.xml`。

编辑器支持在敌人 `Behavior` 中设置 `attack` / `attackPerRound`，敌人行动伤害选择 `EnemyAttackScale` 并填写系数；玩家牌型和遗物不会提供该数值来源。状态可分别配置 `IncomingAttackDamagePerStack.rate`、`StackDecay.timing/timingSubject/stacks`，两项能力与旧周期伤害相互独立。

界面与占位美术是独立 H5 实现，不接入 Unity 场景、图集、动画或资源导入。四张角色 PNG 均为 192×192，合计约 187 KiB；加上遗物和状态共用的 SVG 图标表，全部图像资源共 194,071 字节（约 189.5 KiB），背景与受伤、治疗、加盾、行动和召唤动效由 CSS 绘制。默认遵循系统“减少动态效果”设置，也可用“动效”按钮关闭。原始大图不入库，生成来源及完整提示词见 [占位资源说明](web/assets/README.md)。

试玩会话保存在本机 C# 进程内存中，可点击“结束试玩”释放。最多同时保留 16 场，闲置 2 小时到期，每场最多提交 4096 次行动。重启服务后需要重新开局；网页草稿仍按原方式保存。多个浏览器标签页的对局相互独立。现在可用下方管理员面板修改当前手牌和牌堆；独立试玩仍不提供撤回操作、批量模拟或完整对局存档。

## 对局管理员

展开战斗下方的「管理员修改」，读取当前状态后，可修改双方生命/生命上限/护盾、玩家金币和持有遗物，并编辑手牌、牌库、弃牌堆。遗物按列表顺序结算；卡牌可改牌面/标记、复制、移除、移动或排序，编辑器中牌库第一张是下一张摸到的牌。预览不会提交；应用时整批校验并原子替换，失败不会留下部分修改。直接修正不消耗行动点、不抽随机数，也不执行普通攻击/复活触发；把生命设为零只改变胜负结果，不发放节点金币。

单局与冒险战斗使用同一面板和 C# `BattleSession.ApplyAdmin` / `PreviewAdmin`。冒险经 `BattleAdventureSession.ApplyAdmin(..., preview: true/false)` 同步持久状态：生命、生命上限、金币、遗物保留到后续节点；改手牌/牌库/弃牌堆只影响当前战斗，不改变永久构筑。地图、商店和休息点仅开放生命/生命上限、金币、遗物，Reward 和终局不再接受修改。普通 XML 表单仍只影响下一次开局。

HTTP 沿用 `/api/playtest`、`/api/adventure` 及本机 `X-Editor-Token` / 同源检查，使用显式管理员操作：

- `admin-state`：以 `sessionId/runId/revision` 读取管理员快照；仅此投影返回真实牌序与实例 ID、卡牌/遗物目录，普通试玩快照只返回牌堆汇总。
- `admin-preview`：额外提交 `patch`，返回原 `battle` / `adventure` 与候选 `admin`、`preview.legal`；不返回或覆盖存档。
- `admin`：提交同一 `patch`，成功推进版本一次并返回新快照；冒险同时返回包含该管理员命令的可恢复存档。冒险战斗须同时提交 `battleRevision`，防止覆盖已经变化的战斗。

```json
{
  "op": "admin",
  "sessionId": "窗口 UUID",
  "runId": "当前 runId",
  "revision": "当前 revision",
  "patch": {
    "vitals": [{"unit": "hero", "health": "800", "maxHealth": "1200", "block": "50"}],
    "gold": [{"owner": "hero", "amount": "9007199254740993"}],
    "zones": [{"owner": "hero", "kind": "hand", "cards": [{"definitionId": "standard:1:14"}]}],
    "relics": [{"owner": "hero", "items": [{"definitionId": "11004", "charges": 3}]}]
  }
}
```

补丁中未提供的部分保持原状；提供的区域/道具列表是完整替换，空列表表示清空。已存在卡牌/遗物填写 `instanceId` 保留其身份和未填写状态；省略实例 ID 表示新建，使用配置目录里的 `definitionId`。跨牌区移动需同批提交来源和目标区域；协议的牌库顺序是底→顶，最后一张先摸。生命/护盾/金币/成长值均使用十进制字符串，避免浏览器损失 64 位精度。条目数量、重复唯一道具、生命范围和实例归属仍由规则验证。

该接口独立于普通玩家动作；联网宿主应只向已授权的管理员暴露它。现有本地工坊的 token 表示本机工具访问权，尚不包含远程账号角色系统。

## 局外冒险

顶部「局外冒险」打开同一服务的 `/adventure` 页面。布局参考[局外交互稿](https://moonton.feishu.cn/docx/EQordOsHeobymRxxAubc2l4MnTb)，复用现有小图和战场组件，未添加 Unity 表现或大型图片资源。

1. 主菜单可开始、继续、查看塔罗图鉴。开始时先手动选角色和已解锁天赋，未选择时不能确认。当前标准配置提供一名角色、初始愚者（生命 +20%）及两个通关后解锁的示例天赋。
2. 地图按章节显示菱形节点和连线，只能进入高亮的可达节点；未来节点只显示战斗、精英、首领、商店、休息类型。标准三章各有三场普通战、一场精英、一间商店、一处休息和一场首领战。
3. 战斗仍调用现有 `BattleSession`，胜利奖励只结算一次。下一场保留剩余血量、永久牌组及遗物；护盾、临时状态和怪物塞入的本场废牌不带入后续战斗。
4. 商店可买卖遗物，或为永久牌组撕毁、印卡、染色；服务价格按整次冒险累计使用次数递增。休息点选择一项收益并确认后才能继续，每个休息点只领一次。
5. 旅程自动保存到当前浏览器；主菜单可导出、导入存档。恢复由 C# 重放操作并验证配置指纹与结果，失败不会覆盖当前旅程。网络结果不明确时先同步权威状态，不自动重发购买或行动。
6. 主菜单的「冒险配置」可导入、编辑、导出局外 XML，或载入磁盘标准配置，下次开局生效。战斗配置与单局入口统一引用磁盘最新日期的 `StandardSingleBattle-YYYY-MM-DD.xml`（缺少日期文件才回退 `StandardSingleBattle.xml`）；不会使用配置编辑器尚未提交到该文件的草稿。存档包含开局时的两份 XML，恢复时继续使用原配置。

现有目标分数制 `Runs` 模块仍保留。这里新增的 `BattleAdventureSession` 专门承接生命战斗和跨场构筑；HTTP `/api/adventure` 只做传输适配，金币、涨价、路线、奖励、解锁均不在 JavaScript 计算。规则与 XML 契约见[局外模块说明](../../Engine/Runtime/Composition/Adventure/README.md)。

默认节点顺序、奖励、商品价格、休息收益、后两章敌人血量倍率和两个新塔罗的效果是验证占位值，可以修改。暂未接入绝杀回收、推币机、高风险博弈、完整塔罗内容表或账号云存档。

## 导入与数据保护

- XML 文档是编辑数据源，表单编辑不会丢弃未知属性、子项和注释。未知/不适用字段在界面提示，可检查后显式移除。
- 修改能力类型或触发时机不会静默删除已有参数。需要清理的不适用字段会保留，正式导出由 C# 阻止。
- XML 语法/根格式无法读取时，当前内容包不被覆盖，原文保留在源码区供修复；规则错误但语法可读的内容作为草稿载入。
- “XML 预览”可查看或编辑完整文本；应用后重新生成对应当前文本的诊断位置。
- 草稿同时保存当前内容和未应用的源码。支持下载/恢复 `.draft.json`，也可在源码区下载明确标为 `.draft.xml` 的未校验文本。
- 草稿保存在当前浏览器、当前地址的 localStorage，可能受隐私模式/配额/清理影响；保存失败会提示下载备份。跨电脑/浏览器请使用文件备份。
- 支持最近 40 次内容修改撤销/重做，刷新后不保留撤销历史。服务离线仍保留表单和草稿；不能把离线当成校验通过。
- 数值作为字符串往返，避免 JavaScript 大整数精度损失。XML 格式化可能改变缩进和属性表示，但不把未知数据自动转换成“已支持”。

## 技术边界

```text
浏览器：schema.js 表单描述 + model.js XML 编辑 + app.js 交互
    POST /api/validate（当前 XML）
ASP.NET Core 本机 HTTP 服务（长度/来源检查、进程超时）
    .NET CompilerBridge 子进程
现有 BattleContentXmlReader → BattleContentCompiler
    统一诊断 / 内容指纹

浏览器：playtest.js 选牌、操作、状态与记录
    POST /api/playtest（JSON 请求）
ASP.NET Core 本机服务 → 常驻 .NET PlaytestBridge 子进程（逐行 JSON）
    BattleContentFactory → BattleSession → 现有规则引擎
```

- `CompilerBridge.cs` 仅投影诊断和现有枚举/默认计分/标准牌面元数据，不实现战斗或复制规则校验算法。
- HTML 的字段可见性、类型化引用和中文说明属于编辑体验；编译器仍检查完整内容包，包括未使用的定义和实际编成组合。
- `PlaytestBridge.cs` 及相关工具目录文件只负责会话管理、JSON 投影与交互适配。规则程序集从 `Engine/Runtime` 按十个独立项目编译；本工具不复制或改写规则模型。
- 试玩请求使用 `sessionId / runId / revision` 校验局次及版本，重复提交和旧局请求不会再次消耗资源。预览在临时会话执行，不提交状态。网络错误后查询权威状态，不自动重发行动。
- 页面没有第三方 CDN、统计服务或外部请求。服务不接收文件路径，不提供写项目文件或任意静态文件读取接口。
- 导入/校验结果绑定内容修订；过期响应不会覆盖新修订。校验服务失败、超时或不可用时不会导出为正式内容。
- 为保护本机接口，服务检查 Host、同源 Origin 和页面会话令牌；不开放 CORS。CSP 禁止内联脚本和外部连接，名称/诊断通过文本节点呈现。
- 当前只支持单个 schema v1 内容包；不提供协作、对局中热更新、多人草稿合并、批量平衡模拟或自动迁移旧 SO。网页验证规则与配置，Unity 动画、输入和场景绑定仍需在 Unity 中验证。
