# 战斗内容工坊（本地 HTML 配置工具）

外部配置工具：十类中文表单、关联配置选择、XML 导入/导出、浏览器草稿、统一 C# 校验和对局试玩。试玩直接运行现有纯 C# 规则引擎，无需打开 Unity；不读写 Unity SO、场景或战斗存档。

## 启动

Windows 双击仓库根目录 `start.cmd`；macOS 双击 `start.command`。缺少 .NET 10 SDK 时，启动器从 Microsoft 官方下载安装到本仓库 `.runtime/dotnet`，随后构建并打开默认浏览器。不需要 Unity、Python、Mono 或 Node；首次启动需要联网。

默认地址 **http://127.0.0.1:18765**，请保留终端窗口。启动失败可以按 R 重试。规则源码修改后重启服务；XML 修改后重新开局。详细参数与排错见 [一键启动](../../scripts/README.md)。

端口被占用时使用 `--port 18766`；浏览器草稿按地址/端口隔离，换端口前请下载备份。请使用启动器输出的 `127.0.0.1` 地址。

## 策划使用流程

1. 没有本地草稿时，首次打开自动载入 `Engine/Content/StandardSingleBattle.xml`；也可点击“载入功能示例”熟悉配置，或导入现有 XML。已有草稿会保留并提示恢复。
2. 左侧按战斗配置、角色与构筑、战斗能力、基础规则分组；搜索名称或 ID，打开具体条目。
3. 修改中文表单；空白可选字段表示继承默认值，显式填入 `0` 与留空不同。高级参数默认折叠。
4. 引用可输入 ID、用候选列表选择、打开可搜索的选择窗口，或点击 `+` 新建后自动引用；“查看”可跳转到定义。侧栏展示引用和被引用关系。
5. 编辑后自动延时调用 C# 校验，也可手动点击“校验内容”。点击错误或警告定位配置；字段级检查只提示输入，不能代替 C# 语义校验。
6. “保存草稿”或 Ctrl/⌘ S 保存本浏览器草稿；编辑会自动保存。第一次打开已有草稿时先提示恢复，不自动覆盖旧草稿。
7. “导出 XML”对当前修订重新执行 C# 校验，只有通过才下载。警告可导出；错误不能导出。源码区有未应用内容时，需要先应用或放弃修改。

十类内容：计分规则、公共战斗规则、牌型效果、状态配置、遗物配置、玩家模板、敌人模板、初始牌组、初始构筑、对局配置。嵌套行为、条件、效果与目标用相同表单编辑，可新增、移除和上下调整顺序。新建牌型规则会生成十种牌型；自定义计分由当前 C# 默认表展开；牌组可以一次添加标准 52 张牌，再编辑单张。

牌型步骤 ID 与效果顺序分开，重排不改 ID。遗物步骤选择器的“浏览步骤来源”只帮助列出指定规则/牌型的步骤，不写入遗物配置，也不假定所有玩家使用同一套牌型规则。修改/移除被匹配的步骤会展示可能受影响的遗物条目，实际对局组合仍由 C# 校验。

定义 ID 重命名时，会询问是否同步更新同类型引用；有引用的定义必须选择替代定义后才能删除。显示名称可自由修改。新增和复制自动生成不冲突的标识；复制构筑不会运行或消耗遗物。

## 对局试玩

1. 打开“对局试玩”，点击试炼卡片或下拉框选择对局。标准 XML 内置轮换小怪、护甲召唤精英、暴食 Boss 三场试炼，共用标准玩家、52 张牌组和单局规则。已有其他配置时可用“载入标准试炼”载入；有未保存编辑会先提示确认。选择试炼不会自动替换正在进行的对局，点击“用当前配置开新局”才生效。
2. 填写固定种子并开局。工具会重新校验当前内容包，成功后才替换旧对局；失败时显示诊断并保留原对局。XML 预览中的修改需要先应用。
3. 按当前阶段摸牌、点选手牌，查看牌型和结算预览，再出牌或弃牌。需要手动选敌时，按提示选择每组目标；多玩家配置可切换当前可行动玩家。结束出牌阶段后，按规则保留或整理手牌，再完成回合。
4. 横版战场左侧是玩家，右侧是敌人，敌人头顶显示下一次行动意图。生命条、护盾、增益/减益、顶部遗物图标随真实规则状态更新；悬停或键盘聚焦图标查看详情。展开底部“战斗记录”查看每步结算。
5. 暴食 Boss 默认将废牌塞入弃牌堆，牌库耗尽后才会洗回。塞牌时显示即时提示，牌堆角标显示废牌数量；点击牌库或弃牌堆可查看按牌面合并的内容，不展示摸牌顺序。废牌进入手牌后显示独立“废牌”卡面，明确标注不可出牌、可弃牌。 在敌人行为的“生成卡牌”中可设置放入区域和插入位置：抽牌堆支持随机洗入、牌顶、牌底，也可直接入手。抽牌堆不填位置时默认随机洗入；标准 Boss 仍默认进弃牌堆。详见[塞牌配置](../../Engine/Runtime/Composition/Content/EnemyBehavior.md#塞牌)。
6. 表单修改不会改变正在进行的对局。重开时应用当前配置；同一配置和种子、同样的操作会重现相同发牌及结算。

界面与占位美术是独立 H5 实现，不接入 Unity 场景、图集、动画或资源导入。四张角色 PNG 均为 192×192，合计约 187 KiB；加上遗物和状态共用的 SVG 图标表，全部图像资源共 194,071 字节（约 189.5 KiB），背景与受伤、治疗、加盾、行动和召唤动效由 CSS 绘制。默认遵循系统“减少动态效果”设置，也可用“动效”按钮关闭。原始大图不入库，生成来源及完整提示词见 [占位资源说明](web/assets/README.md)。

试玩会话保存在本机 C# 进程内存中，可点击“结束试玩”释放。最多同时保留 16 场，闲置 2 小时到期，每场最多提交 4096 次行动。重启服务后需要重新开局；网页草稿仍按原方式保存。多个浏览器标签页的对局相互独立。第一版不提供指定起手牌、撤回操作、批量模拟或完整对局存档。

## 导入与数据保护

- XML 文档是编辑数据源，表单编辑不会丢弃未知属性、子项和注释。未知/不适用字段在界面提示，可检查后显式移除。
- 修改能力类型或触发时机不会静默删除已有参数。需要清理的不适用字段会保留，正式导出由 C# 阻止。
- XML 语法/根格式无法读取时，当前内容包不被覆盖，原文保留在源码区供修复；规则错误但语法可读的内容作为草稿载入。
- “XML 预览”可查看或编辑完整文本；应用后重新生成对应当前文本的诊断位置。
- 草稿同时保存当前内容和未应用的源码。支持下载/恢复 `.draft.json`，也可在源码区下载明确标为 `.draft.xml` 的未校验文本。
- 草稿保存在当前浏览器、当前地址的 localStorage，可能受隐私模式/配额/清理影响；保存失败会提示下载备份。跨电脑/浏览器请使用文件备份。
- 支持最近 40 次内容修改撤销/重做，刷新后不保留撤销历史。服务离线仍保留表单和草稿；不能把离线当成校验通过。
- 数值作为字符串往返，避免 JavaScript 大整数精度损失。XML 格式化可能改变缩进和属性表示，但不把未知数据自动转换成“已支持”。

## 技术边界

```text
浏览器：schema.js 表单描述 + model.js XML 编辑 + app.js 交互
    POST /api/validate（当前 XML）
ASP.NET Core 本机 HTTP 服务（长度/来源检查、进程超时）
    .NET CompilerBridge 子进程
现有 BattleContentXmlReader → BattleContentCompiler
    统一诊断 / 内容指纹

浏览器：playtest.js 选牌、操作、状态与记录
    POST /api/playtest（JSON 请求）
ASP.NET Core 本机服务 → 常驻 .NET PlaytestBridge 子进程（逐行 JSON）
    BattleContentFactory → BattleSession → 现有规则引擎
```

- `CompilerBridge.cs` 仅投影诊断和现有枚举/默认计分/标准牌面元数据，不实现战斗或复制规则校验算法。
- HTML 的字段可见性、类型化引用和中文说明属于编辑体验；编译器仍检查完整内容包，包括未使用的定义和实际编成组合。
- `PlaytestBridge.cs` 及相关工具目录文件只负责会话管理、JSON 投影与交互适配。规则程序集从 `Engine/Runtime` 按十个独立项目编译；本工具不复制或改写规则模型。
- 试玩请求使用 `sessionId / runId / revision` 校验局次及版本，重复提交和旧局请求不会再次消耗资源。预览在临时会话执行，不提交状态。网络错误后查询权威状态，不自动重发行动。
- 页面没有第三方 CDN、统计服务或外部请求。服务不接收文件路径，不提供写项目文件或任意静态文件读取接口。
- 导入/校验结果绑定内容修订；过期响应不会覆盖新修订。校验服务失败、超时或不可用时不会导出为正式内容。
- 为保护本机接口，服务检查 Host、同源 Origin 和页面会话令牌；不开放 CORS。CSP 禁止内联脚本和外部连接，名称/诊断通过文本节点呈现。
- 当前只支持单个 schema v1 内容包；不提供协作、对局中热更新、多人草稿合并、批量平衡模拟或自动迁移旧 SO。网页验证规则与配置，Unity 动画、输入和场景绑定仍需在 Unity 中验证。

## 验证

后端集成（仅开发测试需要 Python 3，随机本机端口；覆盖原 Python 兼容宿主和正式 .NET 宿主）：

```bash
python3 -m unittest discover -s Tools/BattleContentEditor/tests -p 'test_*.py' -v
```

浏览器回归需要额外安装测试依赖 Playwright 与 Chromium。先启动本地服务，再在仓库根目录执行：

```bash
npm ci
npx playwright install chromium
npm run test:browser
npm run test:playtest
npm run test:h5
```

默认使用隔离的无头 Chrome，不连接用户日常浏览器。可用 `EDITOR_URL` 指定测试地址、`PLAYWRIGHT_CHANNEL` 指定渠道、`EDITOR_SCREENSHOT` 指定截图路径。浏览器测试会在隔离上下文里生成草稿与下载；服务本身不会保存这些文件。

H5 场景回归另覆盖标准三试炼选择、横向布局、192px 资源及体积预算、召唤与废牌、零护盾、战斗记录、动效开关、系统减少动画、375px 窄屏与 XML 名称安全。

原规则层回归：

```bash
bash Tools/test-poker-engine.sh BattleContentXmlReaderTests BattleContentEffectCompilationTests BattleContentCombinationTests BattleContentIntegrationTests
```

配置编辑器验证：浏览器流程 26 项通过，包括首访默认 XML 延迟返回时保留表单与未应用源码修改；原后端集成基线 10 项、XML 初次接入规则基线 154 项通过。浏览器检查覆盖十类表单、引用重命名/删除、未知字段与注释保留、导入修复、草稿恢复、长整数、过期响应、离线导出阻止和 1100px 布局。

对局试玩与 H5 本轮验证（2026-10-19）：宿主集成 27 项、原网页试玩流程 15 项、H5 场景 15 项通过，覆盖预览纯净性、固定种子、配置冻结、失败重开保留、多玩家与多目标、请求丢包恢复、结束试玩、刷新释放会话，以及三场标准怪物试炼。

牌型、敌人和遗物效果均可配置“净化负面状态”（Cleanse），状态标签可选“负面”（Negative）。净化移除 Negative/Control，保留增益。编成中的遗物按获得顺序填写；数值逐项结算，触发优先级只影响同一件遗物内部。
